<StoryHeader title="useBreakpoint" />

<Ink as="span">Returns the current viewport breakpoint name — <code>"phone"</code>, <code>"tablet"</code>, <code>"laptop"</code>, or <code>"desktop"</code> — and re-renders the component when the viewport crosses a band. Reads <code>window.innerWidth</code> directly via <code>useSyncExternalStore</code>, so it needs <Ink as="span" weight="semibold">no <code>StylesProvider</code></Ink> (unlike <code>useDevice</code> / <code>useTheme</code>).</Ink>

<Line />

<Ink as="h2">Usage</Ink>

```tsx
import { useBreakpoint } from "nice-react-styles"

function Gallery() {
  const bp = useBreakpoint()
  return bp === "phone" ? <Carousel /> : <Grid />
}
```

<Ink as="span"><code>BreakpointName</code> is <code>"phone" | "tablet" | "laptop" | "desktop"</code>, smallest to largest. The breakpoint constants are exported too:</Ink>

```tsx
import { useBreakpoint, BREAKPOINT_DESKTOP } from "nice-react-styles"

const bp = useBreakpoint()
const wide = bp === BREAKPOINT_DESKTOP
```

<Line />

<Ink as="h2">Prefer CSS for styling — reach for this only to swap trees</Ink>

<Ink as="span"><code>useBreakpoint</code> runs in JS, so it carries costs the CSS layer doesn't:</Ink>

<ul>
  <li><Ink as="span"><Ink as="span" weight="semibold">SSR snapshot is <code>"phone"</code></Ink> (phone-first). The server renders the phone</Ink></li>
</ul>
  branch; the client re-renders on hydration if the viewport is wider — a
  potential flash for non-phone branches.
<ul>
  <li><Ink as="span">JS-gated content isn't in the initial HTML.</Ink></li>
  <li><Ink as="span">The subtree re-renders on every viewport cross.</Ink></li>
</ul>

<Ink as="span">So it's the <Ink as="span" weight="semibold">escape hatch</Ink> for cases CSS can't express — swapping component <Ink as="span" weight="semibold">identity / behavior</Ink> (a carousel vs a grid, different event wiring), or <Ink as="span" weight="semibold">avoiding mounting</Ink> an expensive subtree on the wrong band (CSS <code>display: none</code> still mounts it and runs its effects). For purely visual differences, prefer the CSS layer:</Ink>

<Ink as="h2">SSR</Ink>

<Ink as="span">The server snapshot is always <code>"phone"</code>. If the server rendered at a larger breakpoint, the component re-renders on hydration once the client snapshot takes over. No <code>window</code> access happens during SSR.</Ink>
