<StoryHeader title="useDevice" />

<Ink as="span">Reads the mobile state published by <code>StylesProvider</code>. Returns <code>{"{ isMobile }"}</code>. When <code>StylesProvider</code> is given <code>detectDevice</code>, it runs detection once and shares the result through context — so every descendant reads one shared value, with no separate provider to wire and no per-component detection. This is the only device binding; detection lives inside <code>nice-react-styles</code>.</Ink>

<Line />

<Ink as="h2">Enable detection on the provider</Ink>

```tsx
import { StylesProvider } from "nice-react-styles"

<StylesProvider detectDevice>
  <App />
</StylesProvider>
```

<Ink as="span"><code>detectDevice</code> defaults to <code>false</code>. When off, no detection runs and no resize listener is registered — <code>useDevice()</code> returns <code>{"{ isMobile: false }"}</code>.</Ink>

<Ink as="h2">Read it anywhere below</Ink>

```tsx
import { useDevice } from "nice-react-styles"

function Nav() {
  const { isMobile } = useDevice()
  return isMobile ? <HamburgerMenu /> : <FullNavBar />
}
```

<Ink as="span">No prop drilling — every component under the <code>StylesProvider</code> reads the same <code>isMobile</code> directly.</Ink>

<Line />

<Ink as="h2">What detection checks</Ink>

<Ink as="span"><code>detectDevice</code> runs detection once and keeps it current on resize / orientation / DevTools-emulation changes — a single shared listener for the whole tree. A viewport is mobile when the user-agent matches a known mobile identifier, <Ink as="span" weight="semibold">or</Ink> the device has touch and a viewport ≤ 640px (the phone band). Debug overrides force mobile on: <code>?mobile=true</code> in the URL, or <code>localStorage.setItem("debug-mobile", "true")</code>.</Ink>
