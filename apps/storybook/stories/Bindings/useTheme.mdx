<StoryHeader title="useTheme" />

<Ink as="span">The theme sibling of <a href="/?path=/docs/bindings-usedevice--docs" target="_top"><code>useDevice</code></a>. Reads the theme state published by <code>StylesProvider</code> and returns <code>{"{ theme }"}</code> — a theme name (<code>"day"</code>, <code>"night"</code>, or a custom theme), not a boolean, so more themes can be added without a breaking signature change. When <code>StylesProvider</code> is given <code>detectTheme</code>, it detects the OS color-scheme preference (<code>prefers-color-scheme: dark</code>) once and shares it through context — so any descendant reads one shared <code>theme</code> instead of wiring its own <code>matchMedia</code>.</Ink>

<Line />

<Ink as="h2">Enable detection on the provider</Ink>

```tsx
import { StylesProvider } from "nice-react-styles"

<StylesProvider detectTheme>
  <App />
</StylesProvider>
```

<Ink as="span"><code>detectTheme</code> defaults to <code>false</code>. When off, no detection runs and no listener is registered — <code>useTheme()</code> returns <code>{"{ theme: DEFAULT_THEME }"}</code> (<code>"day"</code>).</Ink>

<Ink as="h2">Read it anywhere below</Ink>

<Ink as="span"><code>useTheme()</code> returns the theme <Ink as="span" weight="semibold">name</Ink>. When a component only cares whether it's dark, derive a local <code>isNight</code> from it — it's a one-liner, and not every consumer needs it, so the hook stays name-based:</Ink>

```tsx
import { useTheme } from "nice-react-styles"

function Logo() {
  const { theme } = useTheme()
  const isNight = theme === "night"

  // append "-dark" to the asset when the night theme is active
  return <img src={`/logo${isNight ? "-dark" : ""}.svg`} alt="Logo" />
}
```

<Ink as="span">Keeping <code>isNight</code> local rather than baking it into the hook means branching on <code>theme</code> survives adding more themes later, while dark-only consumers still get a clean boolean.</Ink>

<Ink as="span">Same shape and ergonomics as <code>useDevice</code> — both come from <code>StylesProvider</code>, so a component can read device and theme from one place:</Ink>

```tsx
const { isMobile } = useDevice()
const { theme } = useTheme()
```

<Line />

<Ink as="h2">What it reflects</Ink>

<Ink as="span"><code>theme</code> follows the <Ink as="span" weight="semibold">system color-scheme preference</Ink> (and the default cascade) — it is the reactive equivalent of mapping <code>window.matchMedia("(prefers-color-scheme: dark)").matches</code> to <code>"night"</code> / <code>"day"</code>.</Ink>

<Ink as="span">It does <Ink as="span" weight="semibold">not</Ink> reflect an explicit <a href="/?path=/docs/basics-themes--docs" target="_top"><code>{"<Theme>"}</code></a> pin you apply yourself — pinning is a deliberate override (the theme equivalent of forcing a device state). To force a specific theme on a subtree, use <code>{"<Theme name=\"night\">"}</code>; to react to a per-element effective theme including pins, read the cascade directly (<code>getComputedStyle</code>).</Ink>
