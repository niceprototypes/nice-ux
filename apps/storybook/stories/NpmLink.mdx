# nice-npm-link

A utility to manage npm linking for nice-react components, automatically removing conflicting peer dependencies.

## Overview

`nice-npm-link` (command: `nnl`) is an enhanced npm link tool that:
- Links local packages into your project
- Prevents duplicate React and styled-components issues
- Auto-detects your package manager (npm, yarn, pnpm)
- Provides dry-run mode for safety
- Offers comprehensive logging

## The Problem

When developing components that depend on React and styled-components, using `npm link` often causes issues:

```
Error: Invalid hook call. Hooks can only be called inside the body of a function component.
```

This happens because your app and the linked component each have their own copies of React in `node_modules`, violating React's "one copy" rule.

## The Solution

`nice-npm-link` solves this by:

1. **Moving React to peerDependencies**: Ensures React is provided by the consuming app
2. **Cleaning node_modules**: Removes conflicting packages from the linked package
3. **Using file: protocol**: More reliable than traditional npm link
4. **Smart detection**: Works with CRA, Next.js, and other setups

## Installation

### Global (Recommended)

```bash
npm install -g nice-npm-link
```

### Local (Project-specific)

```bash
npm install --save-dev nice-npm-link
```

## Usage

### Basic Linking

```bash
# Link a local package
nnl ../my-component-library

# Link with full path
nnl /Users/you/projects/my-component-library
```

### Common Options

#### Dry Run
Preview changes without making them:

```bash
nnl --dry-run ../my-component-library
```

#### Clean Only
Just clean conflicts without linking:

```bash
nnl --clean-only ../my-component-library
```

#### Custom Package Manager
Force a specific package manager:

```bash
nnl --manager pnpm ../my-component-library
nnl --manager yarn ../my-component-library
```

#### Custom Exclusions
Override default packages to remove:

```bash
# Replace defaults entirely
nnl --exclude react,react-dom,styled-components ../my-lib

# Add to defaults
nnl --add-exclude @emotion/react,@emotion/styled ../my-lib
```

#### Skip Peer Dependency Check
Don't auto-move React to peerDependencies:

```bash
nnl --skip-peer-check ../my-component-library
```

## Default Behavior

### Packages Removed from Linked Package

By default, these packages are removed from the linked package's `node_modules`:

- react
- react-dom
- scheduler
- react-is
- styled-components
- @emotion/react
- @emotion/styled
- @types/react
- @types/react-dom

### Auto-moved to peerDependencies

These packages are automatically moved from `dependencies` to `peerDependencies` in the linked package:

- react
- react-dom

## Workflow Examples

### Developing a Component Library

```bash
# 1. Navigate to your app
cd ~/projects/my-app

# 2. Link your component library
nnl ../my-component-library

# 3. Start dev mode in the library (if available)
cd ../my-component-library
npm run dev  # or npm run build:watch

# 4. Start your app
cd ../my-app
npm start
```

### Working with Create React App

For CRA apps, you may need to preserve symlinks:

```bash
# Bash/Zsh
export NODE_OPTIONS=--preserve-symlinks
npm start

# Windows (Command Prompt)
setx NODE_OPTIONS "--preserve-symlinks"
npm start

# Or use the script directly
NODE_OPTIONS=--preserve-symlinks npm start
```

### Working with Next.js

Next.js typically handles symlinks well, but if you encounter issues:

```javascript
// next.config.js
module.exports = {
  webpack: (config) => {
    config.resolve.symlinks = false
    return config
  },
}
```

### Unlinking

To unlink, simply update your `package.json` back to the npm version:

```json
{
  "dependencies": {
    "my-component-library": "^1.0.0"  // Change from "file:../my-component-library"
  }
}
```

Then run:

```bash
npm install
```

## Advanced Usage

### Multiple Component Libraries

Link multiple packages:

```bash
nnl ../nice-react-button
nnl ../nice-react-icon
nnl ../nice-react-flex
```

### Monorepo Setup

While nice-npm-link works in monorepos, consider using workspace: protocol instead:

```json
{
  "dependencies": {
    "my-component": "workspace:*"
  }
}
```

### Custom Conflict Resolution

Add packages specific to your setup:

```bash
# If using @mui/material
nnl --add-exclude @mui/material,@mui/system ../my-lib

# If using custom emotion setup
nnl --add-exclude @emotion/cache,@emotion/serialize ../my-lib
```

## Troubleshooting

### Module Not Found

**Problem**: `Cannot find module 'my-component'`

**Solution**: Ensure the linked package has been built:

```bash
cd ../my-component
npm run build
```

### Invalid Hook Call

**Problem**: React hooks error despite linking

**Solution**:
1. Use clean-only to re-clean the linked package:
   ```bash
   nnl --clean-only ../my-component
   ```

2. Check React versions match:
   ```bash
   # In your app
   npm ls react

   # In linked package
   cd ../my-component && npm ls react
   ```

### Stale Cache

**Problem**: Changes not reflecting in app

**Solution**:
```bash
# Clear node_modules and reinstall
rm -rf node_modules package-lock.json
npm install
nnl ../my-component
```

### Watch Mode Not Working

**Problem**: Changes in linked package don't trigger rebuild

**Solution**: Use the library's watch mode:

```bash
cd ../my-component
npm run dev  # or build:watch
```

## Configuration

### Environment Variables

```bash
# Force a package manager
export NPM_LINK_MANAGER=pnpm

# Always use dry-run
export NPM_LINK_DRY_RUN=true
```

### Project .npmrc

Add to your app's `.npmrc`:

```
# Preserve symlinks
node-options=--preserve-symlinks
```

## Best Practices

1. **Always build first**: Build your component library before linking
2. **Use watch mode**: Run `npm run dev` in the library for live updates
3. **Clean regularly**: Run with `--clean-only` if issues arise
4. **Version control**: Don't commit `file:` dependencies
5. **Document setup**: Add linking instructions to your README
6. **Use workspaces for monorepos**: Consider workspace: protocol for permanent setups

## How It Works

### Step-by-Step Process

1. **Detect Package Manager**: Checks for pnpm-lock.yaml, yarn.lock, or defaults to npm
2. **Update peerDependencies**: Moves React/React-DOM from dependencies to peerDependencies
3. **Clean node_modules**: Removes conflicting packages from linked package
4. **Link with file: protocol**: Updates app's package.json with file: reference
5. **Install**: Runs package manager install to link the package
6. **Final cleanup**: One more cleaning pass to ensure no conflicts

### File: Protocol

Instead of npm's symbolic linking, uses file: protocol:

```json
{
  "dependencies": {
    "my-component": "file:../my-component"
  }
}
```

This is more reliable and works better with modern package managers.

## API

### Command Line

```bash
nnl <package-path> [options]
```

### Options

| Option | Description | Example |
|--------|-------------|---------|
| `--dry-run` | Preview without changes | `nnl --dry-run ../lib` |
| `--clean-only` | Only clean conflicts | `nnl --clean-only ../lib` |
| `--exclude <list>` | Override packages to remove | `nnl --exclude react,react-dom ../lib` |
| `--add-exclude <list>` | Add to default exclusions | `nnl --add-exclude @mui/material ../lib` |
| `--manager <pm>` | Force package manager | `nnl --manager pnpm ../lib` |
| `--skip-peer-check` | Skip auto peer dependency move | `nnl --skip-peer-check ../lib` |
| `--help, -h` | Show help | `nnl --help` |

## Package Manager Support

### npm
- Auto-detected from absence of yarn.lock/pnpm-lock.yaml
- Uses npm install for linking

### yarn
- Auto-detected from yarn.lock
- Uses yarn for install operations

### pnpm
- Auto-detected from pnpm-lock.yaml
- Uses pnpm for install operations

For CI, avoid linking. Use published versions or workspace: protocol in monorepos:

```json

    // or

  }
}
```

## Comparison with Alternatives

### vs npm link

| Feature | nice-npm-link | npm link |
|---------|---------------|----------|
| Prevents React duplicates | ✅ Yes | ❌ No |
| Auto cleans node_modules | ✅ Yes | ❌ No |
| Package manager detection | ✅ Yes | ❌ No |
| Dry-run mode | ✅ Yes | ❌ No |
| file: protocol | ✅ Yes | ❌ No (uses symlinks) |

### vs yalc

| Feature | nice-npm-link | yalc |
|---------|---------------|------|
| Setup complexity | Low | Medium |
| Cleaning | Automatic | Manual |
| Live updates | ✅ Yes | ✅ Yes |
| Global installation | Optional | Required |

### vs workspace: protocol

| Feature | nice-npm-link | workspace: |
|---------|---------------|------------|
| Monorepo only | ❌ No | ✅ Yes |
| Cross-project | ✅ Yes | ❌ No |
| Setup | Quick | Requires monorepo |
| Flexibility | High | Medium |
