<Ink as="h3">Setup</Ink>

Add it to `addons` — the entry loads both its manager and preview halves:

```ts
// .storybook/main.ts
const config = {
  addons: [
    "@storybook/addon-links",
    "storybook-dark-mode",
    "nice-storybook-navigation",
  ],
}

export default config
```

Peers: `storybook` ≥ 10, `storybook-dark-mode`, `@storybook/addon-links`,
`react`, `react-dom`, `styled-components`.

<Ink as="h3">Sequences</Ink>

Back / next are not automatic — the bar walks ordered lists you supply, so a
guided path can differ from sidebar order and a page outside every sequence
simply renders no links.

```ts
// .storybook/preview.ts
export const parameters = {
  storyNavigation: {
    sequences: [
      [
        { id: "basics-welcome--docs", label: "Welcome" },
        { id: "basics-reset--docs", label: "Reset" },
        { id: "basics-tokens--docs", label: "Tokens" },
      ],
    ],
  },
}
```

Ids are your own story ids — the slug Storybook derives from each page's
`<Meta title>`.

<Ink as="h3">Why it needs a manager half</Ink>

The bar renders in the preview iframe, but the sidebar, the editor and the
settings tabs all belong to the manager. The preview cannot reach them, so each
control emits on the addons channel and the manager entry maps it to the
matching `api` call. The dark-mode toggle rides the same bridge.

That split is also why the bar can show sidebar state: the manager answers with
the current value rather than the preview guessing.
