### Setup

Add it to `addons` — it is a preset, so there is no manager or preview entry to
register:

```ts
// .storybook/main.ts
const config = {
  addons: [
    "storybook-dark-mode",
    "nice-storybook-spinner",
  ],
}

export default config
```

To pass options, use the object form of the entry:

```ts
addons: [
  { name: "nice-storybook-spinner", options: { hold: false, timeout: 8000 } },
]
```

Peer: `storybook` ≥ 10. The spinner is the real `<Icon name="spinner" />` from
`nice-react-icon`, rendered to static markup when the addon is built, with its
size, stroke, duration and day / night colors taken from `nice-styles` tokens at
the same time — so the published package has no dependencies.

### Options

| Option           | Type      | Default | Description |
|------------------|-----------|---------|-------------|
| `hold`           | `boolean` | `false` | Keep the boot overlay (or the held snapshot) up for good. |
| `timeout`        | `number`  | `8000`  | Release after this many ms, whatever the readiness signals say. |
| `viewTransition` | `boolean` | `true`  | Snapshot mode, below. `false` keeps only the opaque overlay: no `@view-transition` rule is injected and `pagereveal` is not handled. |

A `timeout` that is not a finite, non-negative number falls back to `8000`; a
`viewTransition` that is not a boolean falls back to its default.

### Hold for styling

To keep the boot overlay on screen while styling it, use any of these — the
first one present wins. Hold keeps whichever mode is active up: the opaque
overlay, or in snapshot mode the held snapshot with the spinner over it.

1. Query parameter: `?nsbHold=1` (or `true`) holds, `?nsbHold=0` (or `false`)
   releases.
2. localStorage: `localStorage.setItem("nice-storybook-spinner:hold", "true")`
   holds, `"false"` releases.
3. The preset option `hold: true`.

A held overlay ignores every removal path, the timeout included. Clear the key
or load with `?nsbHold=0` to release it.

`window.__NSB` is a read-only debug view of the overlay: `{ theme, hold, mode,
removed }`, where `mode` is `"overlay"` or `"snapshot"` and `removed` names the
signal that took it down and is empty while it is up.

### How it works

The addon is a preset with two hooks. Both put their markup first in the head,
so it runs before any other head content is fetched or parsed.

**`managerHead`** inlines the boot overlay script. It resolves the theme
synchronously from storybook-dark-mode's localStorage store
(`sb-addon-themes-3`) — the stored mode when the user chose it explicitly,
otherwise day — so the overlay's first paint is already in the right theme. It
then mounts the overlay on `<html>` before `<body>` exists.

The overlay comes down once the page behind it is ready: after
`storyRendered` or `docsRendered`, then `document.fonts.ready` (capped at 1s),
then two animation frames, so the first frame without the overlay is a rendered
page. On `storyErrored`, `storyThrewException` or `storyMissing` it is removed
immediately, so Storybook's error display is never covered. After `timeout` ms
it is removed regardless.

**Snapshot mode** (`viewTransition`, manager only). `managerHead` also injects
`@view-transition { navigation: auto }`, which opts the manager into
cross-document View Transitions. When `pagereveal` carries a `viewTransition`,
the boot script removes the opaque overlay and holds the transition instead:
the previous page's snapshot (`::view-transition-old(root)`) stays at full
opacity, the live new page stays invisible, and the spinner — token size and
theme color, no background — shows above the snapshot under its own
`view-transition-name`. The browser blocks pointer and wheel input during the
transition but not the keyboard, so `keydown` / `keyup` are blocked in the
capture phase until the release. The same readiness signals (and `timeout`)
release it with a 180ms cross-fade to the rendered page, and
`skipTransition()` runs afterwards as a safety net. The preview iframe is part
of the snapshot and needs no opt-in.

Snapshot mode covers same-origin navigations — links, `location.assign`, back
and forward — in Chrome / Edge 126+ and Safari 18.2+. A first visit and a reload
never get a View Transition (measured in Chromium 139 and WebKit 26), so they,
and other browsers, get the opaque overlay.

**`previewHead`** handles navigation inside the preview iframe. A permanent
stylesheet hides Storybook's native loaders — the grey docs skeleton
(`.sb-preparing-docs`) and the story spinner (`.sb-preparing-story`) — and
shows `#nsb-preview-spinner` exactly when Storybook would show its own loader.
A script mounts that spinner as the first child of `<body>` as soon as `<body>`
exists, themed like the overlay and following storybook-dark-mode's
`DARK_MODE` event afterwards.

The preview head also carries the boot overlay script, which acts only when
`iframe.html` is opened on its own. `.sb-nopreview` and `.sb-errordisplay` are
never touched.

### Accessibility

Both spinners carry `role="progressbar"` and `aria-busy="true"`, labelled
"Loading Storybook" (boot overlay) and "Loading story" (preview). Under
`prefers-reduced-motion: reduce` the rotation slows to one turn every 2s.
