<Ink as="h3">Setup</Ink>

<Ink as="span">Add it to <code>addons</code> — it is a preset, so there is no manager or preview entry to register:</Ink>

```ts
// .storybook/main.ts
const config = {
  addons: [
    "storybook-dark-mode",
    "nice-storybook-spinner",
  ],
}

export default config
```

<Ink as="span">To pass options, use the object form of the entry:</Ink>

```ts
addons: [
  { name: "nice-storybook-spinner", options: { hold: false, timeout: 8000 } },
]
```

<Ink as="span">Peer: <code>storybook</code> ≥ 10. The spinner is the real <code>{"<Icon name=\"spinner\" />"}</code> from <code>nice-react-icon</code>, rendered to static markup when the addon is built, with its size, stroke, duration and day / night colors taken from <code>nice-styles</code> tokens at the same time — so the published package has no dependencies.</Ink>

<Ink as="span">A <code>timeout</code> that is not a finite, non-negative number falls back to <code>8000</code>; a <code>viewTransition</code> that is not a boolean falls back to its default.</Ink>

<Ink as="h3">Hold for styling</Ink>

<Ink as="span">To keep the boot overlay on screen while styling it, use any of these — the first one present wins. Hold keeps whichever mode is active up: the opaque overlay, or in snapshot mode the held snapshot with the spinner over it.</Ink>

<ol>
  <li><Ink as="span">Query parameter: <code>?nsbHold=1</code> (or <code>true</code>) holds, <code>?nsbHold=0</code> (or <code>false</code>)</Ink></li>
</ol>
   releases.
<ol>
  <li><Ink as="span">localStorage: <code>localStorage.setItem("nice-storybook-spinner:hold", "true")</code></Ink></li>
</ol>
   holds, `"false"` releases.
<ol>
  <li><Ink as="span">The preset option <code>hold: true</code>.</Ink></li>
</ol>

<Ink as="span">A held overlay ignores every removal path, the timeout included. Clear the key or load with <code>?nsbHold=0</code> to release it.</Ink>

`window.__NSB` is a read-only debug view of the overlay: `{ theme, hold, mode,
removed }`, where `mode` is `"overlay"` or `"snapshot"` and `removed` names the
<Ink as="span">signal that took it down and is empty while it is up.</Ink>

<Ink as="h3">How it works</Ink>

<Ink as="span">The addon is a preset with two hooks. Both put their markup first in the head, so it runs before any other head content is fetched or parsed.</Ink>

<Ink as="span"><Ink as="span" weight="semibold"><code>managerHead</code></Ink> inlines the boot overlay script. It resolves the theme synchronously from storybook-dark-mode's localStorage store (<code>sb-addon-themes-3</code>) — the stored mode when the user chose it explicitly, otherwise day — so the overlay's first paint is already in the right theme. It then mounts the overlay on <code>{"<html>"}</code> before <code>{"<body>"}</code> exists.</Ink>

<Ink as="span">The overlay comes down once the page behind it is ready: after <code>storyRendered</code> or <code>docsRendered</code>, then <code>document.fonts.ready</code> (capped at 1s), then two animation frames, so the first frame without the overlay is a rendered page. On <code>storyErrored</code>, <code>storyThrewException</code> or <code>storyMissing</code> it is removed immediately, so Storybook's error display is never covered. After <code>timeout</code> ms it is removed regardless.</Ink>

<Ink as="span"><Ink as="span" weight="semibold">Snapshot mode</Ink> (<code>viewTransition</code>, manager only). <code>managerHead</code> also injects <code>{"@view-transition { navigation: auto }"}</code>, which opts the manager into cross-document View Transitions. When <code>pagereveal</code> carries a <code>viewTransition</code>, the boot script removes the opaque overlay and holds the transition instead: the previous page's snapshot (<code>::view-transition-old(root)</code>) stays at full opacity, the live new page stays invisible, and the spinner — token size and theme color, no background — shows above the snapshot under its own <code>view-transition-name</code>. The browser blocks pointer and wheel input during the transition but not the keyboard, so <code>keydown</code> / <code>keyup</code> are blocked in the capture phase until the release. The same readiness signals (and <code>timeout</code>) release it with a 180ms cross-fade to the rendered page, and <code>skipTransition()</code> runs afterwards as a safety net. The preview iframe is part of the snapshot and needs no opt-in.</Ink>

<Ink as="span">Snapshot mode covers same-origin navigations — links, <code>location.assign</code>, back and forward — in Chrome / Edge 126+ and Safari 18.2+. A first visit and a reload never get a View Transition (measured in Chromium 139 and WebKit 26), so they, and other browsers, get the opaque overlay.</Ink>

<Ink as="span"><Ink as="span" weight="semibold"><code>previewHead</code></Ink> handles navigation inside the preview iframe. A permanent stylesheet hides Storybook's native loaders — the grey docs skeleton (<code>.sb-preparing-docs</code>) and the story spinner (<code>.sb-preparing-story</code>) — and shows <code>#nsb-preview-spinner</code> exactly when Storybook would show its own loader. A script mounts that spinner as the first child of <code>{"<body>"}</code> as soon as <code>{"<body>"}</code> exists, themed like the overlay and following storybook-dark-mode's <code>DARK_MODE</code> event afterwards.</Ink>

<Ink as="span">The preview head also carries the boot overlay script, which acts only when <code>iframe.html</code> is opened on its own. <code>.sb-nopreview</code> and <code>.sb-errordisplay</code> are never touched.</Ink>

<Ink as="h3">Accessibility</Ink>

<Ink as="span">Both spinners carry <code>role="progressbar"</code> and <code>aria-busy="true"</code>, labelled "Loading Storybook" (boot overlay) and "Loading story" (preview). Under <code>prefers-reduced-motion: reduce</code> the rotation slows to one turn every 2s.</Ink>
