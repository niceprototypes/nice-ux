# Vite Watcher

```bash
npm install -D nice-vite-watcher
```

### Setup

```js
import { viteWatcher } from "nice-vite-watcher"
```

---

## The Problem

When developing with `npm link` or `file:` dependencies, Vite's dev server doesn't detect changes in linked packages. You're forced to restart the dev server every time you modify a linked package.

#### The Solution

This plugin watches the dist folder of linked packages and triggers a browser reload when they rebuild.

```text
Developer edits source
       ↓
Package build runs
       ↓
dist/ updates
       ↓
Plugin detects change (debounced)
       ↓
Browser reloads
```

#### Vite Only

This plugin is for Vite projects (including Storybook with Vite). For webpack/CRA projects, use `nice-toolkit --dev --watch` instead.

---

## viteWatcher

Creates the Vite plugin that watches linked package dist folders.

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import { viteWatcher } from 'nice-vite-watcher'

export default defineConfig({
  plugins: [
    viteWatcher({
      packages: {
        'nice-react-button': '/Users/me/Code/nice-react-button',
        'nice-react-icon': '/Users/me/Code/nice-react-icon',
      },
      verbose: true,
    }),
  ],
})
```

#### Options

```typescript
{
  packages: Record<string, string>  // Package name → local path
  watchDir?: string                 // Subdirectory to watch (default: 'dist')
  verbose?: boolean                 // Log changes (default: false)
  debounce?: number                 // Debounce delay in ms (default: 300)
}
```

## getSourceAliases

Generates Vite resolve aliases pointing to package source files. Use this for packages without special build transforms to get true HMR with state preservation.

```typescript
import { getSourceAliases } from 'nice-vite-watcher'

const linkedPackages = {
  'nice-react-button': '/Users/me/Code/nice-react-button',
  'nice-react-icon': '/Users/me/Code/nice-react-icon',
}

// Only alias packages that don't need build transforms
const aliases = getSourceAliases(
  linkedPackages,
  ['nice-react-button'],  // These get aliased to src/
  'index.ts'              // Entry point (default)
)

// Result:
// { 'nice-react-button': '/Users/me/Code/nice-react-button/src/index.ts' }
```

## Combining Both Approaches

For the best experience, use source aliases for simple packages (true HMR) and dist watching for packages with build transforms (SVGR, PostCSS, etc.).

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import { viteWatcher, getSourceAliases } from 'nice-vite-watcher'

const linkedPackages = {
  'nice-react-button': '/Users/me/Code/nice-react-button',
  'nice-react-icon': '/Users/me/Code/nice-react-icon',  // Uses SVGR
  'nice-react-flex': '/Users/me/Code/nice-react-flex',
}

// Packages without special build transforms
const sourceAliasable = ['nice-react-button', 'nice-react-flex']

export default defineConfig({
  plugins: [
    viteWatcher({
      packages: linkedPackages,
      verbose: true,
    }),
  ],
  resolve: {
    alias: getSourceAliases(linkedPackages, sourceAliasable),
  },
  optimizeDeps: {
    exclude: Object.keys(linkedPackages),
  },
})
```

#### Strategy Comparison

```text
| Package Type              | Strategy        | HMR Behavior          |
|---------------------------|-----------------|----------------------|
| Simple TypeScript/React   | Source alias    | True HMR (state kept)|
| Uses SVGR, PostCSS, etc.  | Dist watching   | Full reload          |
```

## Storybook Integration

Works with Storybook's Vite builder via `viteFinal` config.

```typescript
// .storybook/main.ts
import { viteWatcher, getSourceAliases } from 'nice-vite-watcher'

const linkedPackages = {
  'nice-react-button': '../react-button',
}

const config: StorybookConfig = {
  framework: '@storybook/react-vite',
  viteFinal: async (config) => {
    config.plugins = [
      ...(config.plugins || []),
      viteWatcher({
        packages: linkedPackages,
        verbose: true,
      }),
    ]
    config.resolve = config.resolve || {}
    config.resolve.alias = {
      ...(config.resolve.alias || {}),
      ...getSourceAliases(linkedPackages, Object.keys(linkedPackages)),
    }
    return config
  },
}
```

## Limitations

#### Full Page Reload

Packages watched via dist (not source-aliased) trigger full reloads, not granular HMR. This resets React component state.

#### Build Pipeline Delay

You need to wait for the linked package's build to complete before changes appear. Run the package in watch mode for faster iteration.

```bash
# In the linked package directory
npm run dev  # or npm run build --watch
```

#### Why Not Source Aliases for Everything?

Source aliases bypass the package's build pipeline, which breaks packages using:

```text
• SVGR — transforms SVG imports to React components
• PostCSS/Tailwind — processes CSS
• Custom Babel plugins — transforms code
• Asset processing — handles images, fonts
```
