<Ink>Eight cache layers can hold stale state in a Nice workspace. Three workspace-level</Ink>
<Ink code>nicely</Ink>
<Ink>operations clear most of them; the rest belong to other owners (the consumer's</Ink>
<Ink code>npm install</Ink><Ink>, npm itself, the user's browser). This page maps which tool clears which layer and gives workflow recipes for the common "something is stale" symptoms.</Ink>

<Ink as="h2">The three <Code code="nicely" language="bash" inlined /> operations</Ink>

<Ink code>nicely --clean</Ink><Ink>,</Ink>
<Ink code>--dedupe</Ink><Ink>, and</Ink>
<Ink code>--build-all</Ink>
<Ink>are the workspace-level toolkit operations. They do not overlap. Each addresses a distinct layer at a distinct location. Mistaking one for another produces silent failure.</Ink>

<Ink as="h3">Distinct targets</Ink>

```bash
nicely --clean    →    <consumer>/node_modules/{.cache, .vite} + processes on declared ports    (layers 3 + 7)
nicely --dedupe       →    <linked-pkg>/node_modules/<singleton>                                     (layer 4)
nicely --build-all       →    <linked-pkg>/dist/                                                        (layer 5)
```

<Ink as="h3">Side-by-side</Ink>

<DataTable

<Ink>The port-kill in</Ink>
<Ink code>nicely --clean</Ink>
<Ink>exists because a running dev server holds an in-memory module graph and repopulates its on-disk cache the moment it's wiped. Wiping cache without killing the server is a no-op against the observable symptom. Use</Ink>
<Ink code>--no-kill</Ink>
<Ink>to wipe caches only (e.g. CI environments).</Ink>

<Ink as="h3">How they combine</Ink>

<Ink>For the "everything is stale" reset, the three are chained in this order:</Ink>

```bash
nicely --clean    # kill dev servers + invalidate layer 3
nicely --dedupe       # resolve layer 4 singleton drift
nicely --build-all       # rebuild layer 5 in tier order
```

<Ink>Then restart any dev server (</Ink><Ink code>npm run dev</Ink>
<Ink>in each consumer) and hard-reload the browser tab.</Ink>

<Ink weight="semibold">Order matters:</Ink>

<ul>
  <li><Ink><Ink weight="semibold"><code>--clean</code> first</Ink> so the consumer's dev server is killed and its build-tool analysis is invalidated before the new dist appears.</Ink></li>
  <li><Ink><Ink weight="semibold"><code>--dedupe</code> before <code>--build-all</code></Ink> so singleton cleanup doesn't run *after* a build that expected the singletons in place.</Ink></li>
  <li><Ink><Ink weight="semibold"><code>--build-all</code> last</Ink> because it produces the artifact every later step reads.</Ink></li>
</ul>

<Ink as="h2">Workflow recipes</Ink>

<Ink as="h4">Dev server is serving stale code after editing a linked package</Ink>

```bash
nicely --clean
```

<Ink>Then restart the dev server (</Ink><Ink code>npm run dev</Ink>
<Ink>inside the consumer) and hard-reload the browser tab.</Ink>
<Ink code>nicely --clean</Ink>
<Ink>killed the old process and wiped the cache; you bring the server back up when ready.</Ink>

<Ink as="h4">"Invalid hook call" or styled-components context mismatch</Ink>

```bash
nicely --dedupe
```

<Ink>The classic duplicate-React-instance error. See</Ink>
<Ink><a href="/?path=/docs/toolkit-2-dedupe--docs" target="_top">Toolkit → Dedupe</a></Ink>
<Ink>for the underlying cause.</Ink>

<Ink as="h4">Consumer reports a missing export from a foundation package after a refactor</Ink>

```bash
nicely --build-all
```

<Ink>The consumer is reading an older</Ink>
<Ink code>dist/</Ink>
<Ink>than the source now produces. Rebuild every linked package in tier order.</Ink>

<Ink as="h4">Fresh clone of the workspace</Ink>

```bash
# In each consumer (website, storybook, website-viveka, …)
npm install

# Once, anywhere in the workspace
nicely --build-all
```

<Ink>The</Ink>
<Ink code>prepare</Ink>
<Ink>hook no longer rebuilds linked packages on consumer installs (see</Ink>
<Ink code>manifest/.nice/reports/npm-install-breaks-consumers.md</Ink><Ink>). New clones must build dists explicitly.</Ink>

<Ink as="h4">Nuclear: I don't know what's wrong</Ink>

```bash
nicely --clean
nicely --dedupe
nicely --build-all
```

<Ink>Restart every dev server. Hard-reload every open browser tab.</Ink>

<Ink>If that doesn't fix it, escalate to a per-consumer reinstall (</Ink><Ink code>rm -rf node_modules package-lock.json && npm install</Ink><Ink>) before reaching for</Ink>
<Ink code>npm cache clean --force</Ink>
<Ink>— the global npm cache is almost never the cause.</Ink>

<Ink as="h2">Why three <Code code="nicely" language="bash" inlined /> operations and not one</Ink>

<Ink>Each addresses a distinct concern with a distinct target directory and a distinct trigger symptom. A single umbrella verb would have to either over-fire (touch directories the symptom doesn't need) or under-fire (miss the directory the symptom does need). The three verbs are exhaustive for the workspace-level operations they cover and orthogonal to one another. Concerns outside the triad — consumer</Ink>
<Ink code>node_modules</Ink>
<Ink>reinstall, global npm cache, browser hard reload — are owned by other tools and intentionally not pulled in.</Ink>
