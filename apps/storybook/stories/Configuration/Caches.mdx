<StoryHeader title="Caches" />

<Ink as="span">Eight cache layers can hold stale state in a Nice workspace. Three workspace-level <code>nicely</code> operations clear most of them; the rest belong to other owners (the consumer's <code>npm install</code>, npm itself, the user's browser). This page maps which tool clears which layer and gives workflow recipes for the common "something is stale" symptoms.</Ink>

<Ink as="h2">The three <Code code="nicely" language="bash" inlined /> operations</Ink>

<Ink as="span"><code>nicely --clean</code>, <code>--dedupe</code>, and <code>--build-all</code> are the workspace-level toolkit operations. They do not overlap. Each addresses a distinct layer at a distinct location. Mistaking one for another produces silent failure.</Ink>

<Ink as="h3">Distinct targets</Ink>

```bash
nicely --clean    →    <consumer>/node_modules/{.cache, .vite} + processes on declared ports    (layers 3 + 7)
nicely --dedupe       →    <linked-pkg>/node_modules/<singleton>                                     (layer 4)
nicely --build-all       →    <linked-pkg>/dist/                                                        (layer 5)
```

    { id: "1", values: [<Ink as="span"><code>nicely --dedupe</code></Ink>, <Ink as="span">Removes duplicate <code>react</code> / <code>react-dom</code> / <code>styled-components</code> / etc. from every linked nice-* package's <code>node_modules</code></Ink>, <Ink as="span">Doesn't rebuild any dist. <Ink as="span">The port-kill in <code>nicely --clean</code> exists because a running dev server holds an in-memory module graph and repopulates its on-disk cache the moment it's wiped. Wiping cache without killing the server is a no-op against the observable symptom. Use <code>--no-kill</code> to wipe caches only (e.g. CI environments).</Ink>

<Ink as="h3">How they combine</Ink>

<Ink as="span">For the "everything is stale" reset, the three are chained in this order:</Ink>

```bash
nicely --clean    # kill dev servers + invalidate layer 3
nicely --dedupe       # resolve layer 4 singleton drift
nicely --build-all       # rebuild layer 5 in tier order
```

<Ink as="span">Then restart any dev server (<code>npm run dev</code> in each consumer) and hard-reload the browser tab.</Ink>

<Ink as="span"><Ink as="span" weight="semibold">Order matters:</Ink></Ink>

<ul>
  <li><Ink as="span"><Ink as="span" weight="semibold"><code>--clean</code> first</Ink> so the consumer's dev server is killed and its build-tool analysis is invalidated before the new dist appears.</Ink></li>
  <li><Ink as="span"><Ink as="span" weight="semibold"><code>--dedupe</code> before <code>--build-all</code></Ink> so singleton cleanup doesn't run *after* a build that expected the singletons in place.</Ink></li>
  <li><Ink as="span"><Ink as="span" weight="semibold"><code>--build-all</code> last</Ink> because it produces the artifact every later step reads.</Ink></li>
</ul>

<Ink as="h2">Workflow recipes</Ink>

<Ink as="h4">Dev server is serving stale code after editing a linked package</Ink>

```bash
nicely --clean
```

<Ink as="span">Then restart the dev server (<code>npm run dev</code> inside the consumer) and hard-reload the browser tab. <code>nicely --clean</code> killed the old process and wiped the cache; you bring the server back up when ready.</Ink>

<Ink as="h4">"Invalid hook call" or styled-components context mismatch</Ink>

```bash
nicely --dedupe
```

<Ink as="span">The classic duplicate-React-instance error. See <a href="/?path=/docs/toolkit-2-dedupe--docs" target="_top">Toolkit → Dedupe</a> for the underlying cause.</Ink>

<Ink as="h4">Consumer reports a missing export from a foundation package after a refactor</Ink>

```bash
nicely --build-all
```

<Ink as="span">The consumer is reading an older <code>dist/</code> than the source now produces. Rebuild every linked package in tier order.</Ink>

<Ink as="h4">Fresh clone of the workspace</Ink>

```bash
# In each consumer (website, storybook, website-viveka, …)
npm install

# Once, anywhere in the workspace
nicely --build-all
```

<Ink as="span">The <code>prepare</code> hook no longer rebuilds linked packages on consumer installs (see <code>manifest/.nice/reports/npm-install-breaks-consumers.md</code>). New clones must build dists explicitly.</Ink>

<Ink as="h4">Nuclear: I don't know what's wrong</Ink>

```bash
nicely --clean
nicely --dedupe
nicely --build-all
```

<Ink as="span">Restart every dev server. Hard-reload every open browser tab.</Ink>

<Ink as="span">If that doesn't fix it, escalate to a per-consumer reinstall (<code>rm -rf node_modules package-lock.json && npm install</code>) before reaching for <code>npm cache clean --force</code> — the global npm cache is almost never the cause.</Ink>

<Line />

<Ink as="h2">Why three <Code code="nicely" language="bash" inlined /> operations and not one</Ink>

<Ink as="span">Each addresses a distinct concern with a distinct target directory and a distinct trigger symptom. A single umbrella verb would have to either over-fire (touch directories the symptom doesn't need) or under-fire (miss the directory the symptom does need). The three verbs are exhaustive for the workspace-level operations they cover and orthogonal to one another. Concerns outside the triad — consumer <code>node_modules</code> reinstall, global npm cache, browser hard reload — are owned by other tools and intentionally not pulled in.</Ink>
