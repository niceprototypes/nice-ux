## Why nice-toolkit?

Nice ecosystem packages use `file:` references for local development. When npm installs these, each package gets its own `node_modules` with duplicate React/styled-components. This causes "Invalid hook call" errors.

```bash
# The problem: duplicate React instances
your-app/node_modules/react           ← App's React
nice-react-tile/node_modules/react    ← Tile's React (CONFLICT!)
nice-react-flex/node_modules/react    ← Flex's React (CONFLICT!)

# The solution: clean all linked packages
node ../toolkit/nice-toolkit --dedupe
```

#### What It Removes

By default, these singleton packages are removed from linked packages:

```bash
• react
• react-dom
• styled-components
• @types/react
• @types/react-dom
```

---

## file: Dependencies

All nice-* packages use `file:` references for interdependencies. This enables live changes to propagate through the dependency chain.

```json
// package.json pattern
{
  "dependencies": {
    "nice-styles": "file:../styles",
    "nice-react-styles": "file:../react-styles"
  },
  "peerDependencies": {
    "nice-react-flex": ">=1.0.0",
    "react": ">=19.2.0"
  },
  "devDependencies": {
    "nice-configuration": "file:../configuration",
    "nice-react-flex": "file:../react-flex"
  }
}
```

#### After Any Dependency Change

Always run `--dedupe` after `npm install` or modifying dependencies:

```bash
node ../toolkit/nice-toolkit --dedupe
```

```bash
# Link a single package
npx nice-toolkit ../react-button

ntk ../react-button

# Link multiple packages
ntk ../react-button
ntk ../react-icon

```

## Workspace operations (triad)

Three non-overlapping commands target the workspace-level concerns. Each addresses a distinct layer at a distinct location. Full topology and recipes in [Caches](/docs/configuration-caches--docs).

```bash
ntk --clean    # consumer caches + dev-server processes  (layer 3 + 7)
ntk --dedupe       # singleton conflicts in linked packages   (layer 4)
ntk --build-all       # rebuild every linked package's dist       (layer 5)
```

For the "everything is stale" reset: `ntk --reset`, then restart any dev server. This chains `--build-all → --dedupe → --clean` in the correct order. See [`--reset`](#-reset) below.

### --clean

Kills any process bound to a dev-server port (discovered from each consumer's `.env` `PORT=` entries and `package.json` `-p` / `--port` flags), then wipes `node_modules/.cache` and `node_modules/.vite` across every consumer in the workspace.

```bash
ntk --clean

# Preview what would be killed and wiped
ntk --clean --dry-run

# Skip the port-kill phase (CI / scripted contexts)
ntk --clean --no-kill
```

The port-kill exists because a running dev server holds an in-memory module graph and repopulates its on-disk cache on the next request — wiping cache without killing the server is a no-op against the observable symptom.

### --dedupe

Recursively find and clean singletons (react, styled-components, etc.) from all `file:` linked packages' `node_modules`. This is the fix for "Invalid hook call" and styled-components context mismatches.

```bash
# Clean all linked packages at once
ntk --dedupe

# Preview what would be cleaned
ntk --dedupe --dry-run
```

### --build-all

Walks the registry in tier order (foundation → context → utility → feature → application) and runs `npm run build` in every linked nice-* package that defines a build script. Replaces the `prepare` hook that was removed from package.json files (see `manifest/.nice/reports/npm-install-breaks-consumers.md`).

Use after a fresh clone, after `--dedupe`, or after a foundation-package refactor.

```bash
ntk --build-all

# Preview without running builds
ntk --build-all --dry-run
```

### --reset

Chains the workspace triad in the correct order: `--build-all → --dedupe → --clean`. Use after any refactor that touches a foundation package (token renames, type narrowing in `nice-styles`, etc.). The order matters — rebuilds first so the new dists exist; dedupe second so any duplicate singletons that crept in during the build cascade are removed; clean last so dev-server caches are flushed and processes are killed before the next restart.

```bash
ntk --reset

# Preview the full sequence without running it
ntk --reset --dry-run
```

Exit code reflects `--build-all`'s result: non-zero if any package failed to build. `--dedupe` and `--clean` always run regardless, since their effects are useful even on partial builds.

## --dedupe

Remove conflicting packages without creating a new link. Useful when packages are already linked via `package.json` `file:` references.

```bash
# Clean a specific linked package
ntk --dedupe ../react-button

# Clean with custom exclusions
ntk --dedupe --add-exclude @emotion/react ../react-button
```

---

## --unlink

Restore packages to their original npm versions. This removes `file:` references and reinstalls from the registry.

```bash
# Unlink all file: dependencies
ntk --unlink

# Preview what would be unlinked
ntk --unlink --dry-run
```

Note: Run this before `npm install` in linked packages, or re-run nice-toolkit after installing dependencies in linked packages.

---

## --exclude / --add-exclude

#### --exclude

Override the default list with your own packages:

```bash
# Only remove React packages (skip styled-components)
ntk --exclude react,react-dom ../my-component
```

#### --add-exclude

Add packages to the default list:

```bash
# Add Emotion packages to defaults
ntk --add-exclude @emotion/react,@emotion/styled ../my-component

# Add Material-UI packages
ntk --add-exclude @mui/material,@mui/icons-material ../my-component
```

## Other Options

#### --dry-run

Preview changes without making them:

```bash
ntk --dry-run ../react-button
ntk --dry-run --dedupe
```

#### --manager

Force a specific package manager (auto-detected by default):

```bash
ntk --manager pnpm ../my-component
ntk --manager yarn ../my-component
ntk --manager npm ../my-component
```

#### --skip-peer-check

Skip automatic peerDependencies enforcement:

```bash
ntk --skip-peer-check ../my-component
```

## --dev

Runs `npm run dev` in all linked packages concurrently. This rebuilds packages automatically when their source files change.

```bash
# Run dev scripts in all linked packages
ntk --dev
```

Packages without a dev script are automatically skipped.

---

## --watch

Watches linked package dist folders and touches a trigger file when changes are detected. This causes webpack/CRA to recompile.

```bash
# Watch dist folders for changes
ntk --watch

# Watch a different folder (default: dist)
ntk --watch --watch-dir build
```

#### Setup for CRA/webpack

Add the trigger file import to your entry point:

```typescript
// src/index.tsx
import './.symlink-trigger.js';
```

Add to `.gitignore`:

```bash
.symlink-trigger.js
```

---

## --dev --watch (Recommended)

Combines both flags: rebuilds packages on source changes AND triggers webpack/CRA recompilation. This is the recommended setup for CRA projects.

```bash
# In package.json
"scripts": {
  "watch:deps": "ntk --dev --watch"
}

# Run alongside your dev server
npm start          # Terminal 1
npm run watch:deps # Terminal 2
```

#### How it works

```bash
Source change in linked package
       ↓
--dev runs rollup/tsc rebuild
       ↓
dist/ files update
       ↓
--watch detects change
       ↓
Touches .symlink-trigger.js
       ↓
CRA/webpack recompiles
```

## --publish

Publishes Nice ecosystem packages to npm in dependency order. Handles version bumping, `file:` dep swapping, building, and restoring local refs.

```bash
# Publish all changed packages (interactive prompts)
ntk --publish

# Publish specific packages
ntk --publish nice-styles,nice-react-styles

# Preview what would be published
ntk --publish --dry-run
```

#### Workflow

```bash
1. Scans ~/Code/nice-* for packages with changes
2. Prompts for version bump (patch/minor/major/skip)
3. Swaps file: deps → semver ranges
4. Builds each package
5. Publishes in dependency order (npm prompts for OTP)
6. Restores file: refs for local development
7. Commits and pushes version changes
```

#### Publish Order

Packages are published bottom-to-top per dependency chain. The publish order is defined in `nice-toolkit/registry.json` and queried via the registry service. Run `ntk --publish --dry-run` to see the current order.

#### Dry Run

Use `--dry-run` or `--dry-publish` to preview without making changes:

```bash
ntk --publish --dry-run
ntk --dry-publish
```

## Troubleshooting

#### Invalid Hook Call Error

Re-run the link command to clean up duplicate React:

```bash
ntk --dedupe
```

#### Changes Not Appearing

Run `--dev` to rebuild linked packages when their source changes:

```bash
# Run in a separate terminal while developing
ntk --dev
```

The `nice-configuration` rollup settings include optimized watch options that prevent file caching issues. Changes should appear immediately.

#### Clear CRA Cache

If changes still don't appear, clear the webpack cache:

```bash
rm -rf node_modules/.cache && npm start
```

#### After Installing Dependencies

When you run `npm install` in a linked package, conflicts return. Either unlink first or re-run nice-toolkit:

```bash
# Option 1: Unlink before installing
ntk --unlink
cd ../react-button && npm install
cd - && ntk ../react-button

# Option 2: Re-clean after installing
cd ../react-button && npm install
cd - && ntk --dedupe
```
