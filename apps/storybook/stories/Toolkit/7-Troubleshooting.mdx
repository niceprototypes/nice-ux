## "Invalid hook call"

More than one copy of React (or styled-components) is loaded. Strip the
duplicates from linked packages:

```bash
ntk --dedupe
```

<HorizontalRule />

## Source changes not appearing

Make sure the rebuild loop is running so a linked package's dist updates on
change:

```bash
ntk --dev --watch   # separate terminal, alongside your dev server
```

If a change still doesn't show, the dev server is holding a stale cache — bounce
it:

```bash
ntk --vite          # wipes .vite + kills the dev-server port; restart after
```

<HorizontalRule />

## Icon (SVG) edits not updating

Editing an SVG **does** rebuild the icon chain under `ntk --dev --watch` —
`nice-icons` regenerates its index and `nice-react-icon`'s dist is rebuilt. The
snag is on the dev-server side: `nice-react-icon` is consumed from **dist** (it
can't be source-aliased because of SVGR), and a Vite dev server such as
Storybook keeps serving its already-transformed copy until it's bounced.

So the fix is to refresh the dev server, not to rebuild again:

```bash
# The rebuilt dist already exists — just make the server re-read it
ntk --vite
# then restart the dev server (Storybook, etc.)
```

Only reach for `ntk --build-icons` when `nice-react-icon`'s dist is actually
stale (e.g. you edited icons while no watcher was running). Do **not** run
`--build-icons` while `--dev --watch` is live — they rebuild the same dist and
race; `--build-icons` will prompt you to stop the watcher first.

<HorizontalRule />

## After installing dependencies in a linked package

`npm install` reintroduces the singleton duplicates. Either unlink first, or
re-dedupe after:

```bash
# Option 1 — unlink before installing
ntk --unlink
cd ../react-button && npm install
cd - && ntk ../react-button

# Option 2 — re-dedupe after installing
cd ../react-button && npm install
cd - && ntk --dedupe
```

<HorizontalRule />

## Everything is stale after a foundation refactor

```bash
ntk --reset   # --build-all → --dedupe → --clean, then restart the dev server
```
