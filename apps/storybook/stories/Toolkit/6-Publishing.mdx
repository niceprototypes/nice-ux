<StoryHeader title="Publishing" />

<Ink as="span">Publishing is driven by per-package bump intent. Each publishable package records what changed in <code>.nice/bump.md</code>; <code>--publish</code> reads those entries to recommend version bumps, then builds and publishes the affected packages in dependency order.</Ink>

<Line />

<Ink as="h2"><Code code="--bump" language="bash" inlined /> — record intent</Ink>

<Ink as="span">Append one entry to the current package's <code>.nice/bump.md</code>. Commit it alongside the change it describes.</Ink>

```bash
nicely --bump minor "Add useBreakpoint hook"
nicely --bump major "Rename breakpoint identifiers small/medium/large to phone/tablet/laptop"
nicely --bump patch "Fix icon stroke width regression"
```

<Ink as="span">Each entry is <code>{"[<timestamp>] <level>: <message>"}</code>. The message doubles as the git commit subject (drop the <code>level:</code> prefix in the commit). Write it for a consumer reading release notes, not as a diff summary. Direct-editing <code>.nice/bump.md</code> is equivalent to <code>--bump</code>.</Ink>

<Line />

<Ink as="h2"><Code code="--publish" language="bash" inlined /></Ink>

<Ink as="span">Publishes changed packages to npm, resolving the full dependency cascade.</Ink>

```bash
# Publish all changed packages (interactive)
nicely --publish

# Publish specific packages (dependents auto-resolved)
nicely --publish nice-styles,nice-react-styles

# Preview without changing anything
nicely --publish --dry-run
```

<Ink as="h4">What it does</Ink>

```bash
1. Resolves affected packages via the reverse file:-dependency graph
2. Reads each .nice/bump.md → recommends a bump level per changed package
   (dependents are auto-patched)
3. Swaps file: deps → semver ranges
4. Builds every affected package in dependency order (no OTP needed)
5. Publishes in rapid succession — prompts once for an npm OTP, re-prompts
   only if it expires mid-run
6. Restores file: refs for local development
7. Clears the consumed .nice/bump.md files, commits the version bump, pushes
```

<Ink as="span">Publish order comes from <code>nice-toolkit/registry.json</code> (bottom-to-top per the dependency chain). Run <code>nicely --publish --dry-run</code> to see the current order and the recommended bumps.</Ink>

<Line />

<Ink as="h2"><Code code="--no-npm" language="bash" inlined /> / <Code code="--dry-publish" language="bash" inlined /></Ink>

```bash
# Bump, build, commit, push — but skip the npm publish step
nicely --publish --no-npm

# Preview the full plan without changing anything
nicely --dry-publish
```

<Ink as="span"><code>--no-npm</code> is useful to verify the pipeline, or to push version bumps and let CI handle the actual npm publish.</Ink>
