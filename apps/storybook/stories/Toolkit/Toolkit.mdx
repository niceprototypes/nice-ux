<StoryHeader title="Toolkit" />

<Ink code>nice-toolkit</Ink>
<Ink>is the CLI that manages local development across the Nice ecosystem — linking packages, resolving singleton conflicts, rebuilding dists, and publishing. Two bin names resolve to the same script:</Ink>
<Ink code>nice-toolkit</Ink>
<Ink>(long form) and</Ink>
<Ink code>nicely</Ink>
<Ink>(short alias).</Ink>

```bash
npm install -g nice-toolkit
```

<Line />

<Ink as="h2">Why it exists</Ink>

<Ink>Nice packages depend on each other through</Ink>
<Ink code>file:</Ink>
<Ink>references so local changes propagate without a publish. The cost is that each linked package installs its own copy of React / styled-components, and multiple React instances throw "Invalid hook call".</Ink>
<Ink code>nicely --dedupe</Ink>
<Ink>removes those duplicate singletons; the rest of the commands cover the build, cache, and publish lifecycle that</Ink>
<Ink code>file:</Ink>
<Ink>linking introduces.</Ink>

```bash
# The problem — duplicate singletons in each linked package
your-app/node_modules/react
nice-react-tile/node_modules/react     ← duplicate (conflict)
nice-react-flex/node_modules/react     ← duplicate (conflict)

# The fix — strip singletons from every linked package
nicely --dedupe
```

<Ink as="h2">Conventions used on these pages</Ink>

<ul>
  <li><Ink><Ink weight="semibold"><code>--dry-run</code></Ink> works on every mutating command — it prints what would happen</Ink></li>
</ul>
  and changes nothing. Reach for it first when unsure.
<ul>
  <li><Ink>Commands act on the packages in <code>nice-toolkit/registry.json</code>. A package</Ink></li>
</ul>
  missing from the registry is invisible to `nicely`.
<ul>
  <li><Ink>Paths are relative to the workspace root (<code>~/nice</code>), e.g. <code>nicely ../react-button</code>.</Ink></li>
</ul>
