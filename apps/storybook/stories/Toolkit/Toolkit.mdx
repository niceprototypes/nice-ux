`nice-toolkit` is the CLI that manages local development across the Nice
ecosystem — linking packages, resolving singleton conflicts, rebuilding dists,
and publishing. Two bin names resolve to the same script: `nice-toolkit` (long
form) and `nicely` (short alias).

```bash
npm install -g nice-toolkit
```

<Line />

## Why it exists

Nice packages depend on each other through `file:` references so local changes
propagate without a publish. The cost is that each linked package installs its
own copy of React / styled-components, and multiple React instances throw
"Invalid hook call". `nicely --dedupe` removes those duplicate singletons; the rest
of the commands cover the build, cache, and publish lifecycle that `file:`
linking introduces.

```bash
# The problem — duplicate singletons in each linked package
your-app/node_modules/react
nice-react-tile/node_modules/react     ← duplicate (conflict)
nice-react-flex/node_modules/react     ← duplicate (conflict)

# The fix — strip singletons from every linked package
nicely --dedupe
```

## Conventions used on these pages

- **`--dry-run`** works on every mutating command — it prints what would happen
  and changes nothing. Reach for it first when unsure.
- Commands act on the packages in `nice-toolkit/registry.json`. A package
  missing from the registry is invisible to `nicely`.
- Paths are relative to the workspace root (`~/nice`), e.g. `nicely ../react-button`.
