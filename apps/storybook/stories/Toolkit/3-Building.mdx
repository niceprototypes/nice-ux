<Ink>Walks the registry tier order (foundation → context → utility → feature → application) and runs</Ink>

<Ink as="h2"><Code code="--build-icons" language="bash" inlined /></Ink>

<Ink>The targeted subset of</Ink>

<Ink>for an icon change. Rebuilds</Ink>
<Ink code>nice-icons</Ink>
<Ink>and everything that transitively depends on it — today</Ink>
<Ink code>nice-react-icon</Ink><Ink>,</Ink>


<Ink as="h4">Dev-watcher auto-stop</Ink>

<Ink code>--build-icons</Ink>
<Ink>and a running</Ink>
<Ink code>nicely --dev</Ink><Ink>/</Ink><Ink code>--watch</Ink>
<Ink>both rebuild the</Ink>
<Ink weight="semibold">same</Ink>
<Ink>dist folders, and every rollup build wipes</Ink>
<Ink code>dist/</Ink>
<Ink>first — so run together they race (transient</Ink>

<Ink code>--build-icons</Ink>
<Ink weight="semibold">stops</Ink>

<Ink code>--vite</Ink>
<Ink>port-kill — then builds, and reminds you to restart it:</Ink>

  <li><Ink>Stop is SIGTERM, then SIGKILL for any straggler.</Ink></li>
  <li><Ink>Pass <Ink weight="semibold"><code>--no-kill</code></Ink> to leave the watcher running and build anyway (you own the</Ink></li>

  dist race).

<Ink as="h2" id="-vite"><Code code="--vite" language="bash" inlined /></Ink>

<Ink>Refresh Vite's optimized-deps cache and bounce running dev servers so a rebuilt linked dist is actually re-bundled. Runs automatically at the end of</Ink>
<Ink code>--build-icons</Ink><Ink>; run it standalone after any out-of-band rebuild.</Ink>

```bash
nicely --vite

# Skip the port-kill phase (wipe caches only)
nicely --vite --no-kill
```

<Ink>Why it's needed: a dev server (Storybook, CRA) holds a transformed copy of a linked package's dist. Rewriting that dist on disk doesn't invalidate the server's copy on its own —</Ink>
<Ink code>--vite</Ink>
<Ink>wipes the</Ink>
<Ink code>.vite</Ink>
<Ink>cache and kills the dev-server port so the next start reads the fresh dist. See</Ink>
<Ink><a href="/?path=/docs/toolkit-7-troubleshooting--docs" target="_top">Troubleshooting → icons not updating</a></Ink><Ink>.</Ink>
