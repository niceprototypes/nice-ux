<Ink as="h2">Guide</Ink>

<Ink as="span">By default Select is a WAI-ARIA select-only combobox: Input rendered read-only with <code>role="combobox"</code>, opening a Popover that holds a <code>role="listbox"</code> List. DOM focus stays on the combobox and the active option is exposed with <code>aria-activedescendant</code>. Set <code>native</code> to render the platform <code>{"<select>"}</code> instead. Both modes are single-value (no <code>multiple</code>), render the chevron in Input's <code>end</code> slot, and call <code>onChange(value, event)</code>. The combobox calls it only when the value changes.</Ink>

<Ink as="span"><code>SelectProps</code> is discriminated on <code>native</code>, so <code>ref</code> is typed for the element rendered: the combobox <code>HTMLInputElement</code>, or the <code>HTMLSelectElement</code>. Every other Input prop passes through (<code>status</code>, <code>filled</code>, <code>width</code>, <code>className</code>, <code>theme</code>, <code>id</code>, …).</Ink>

```jsx
<Select options={options} />          // combobox (default)
<Select native options={options} />   // platform <select>
```

<Ink as="span">Typeahead matches option text by prefix, case-insensitive; characters typed within 500 ms form one search, and Space inside a search is part of it. Disabled options are skipped. Blur, or a pointer press outside, closes without changing the value.</Ink>

<Ink as="span">The combobox has no <code>name</code>. <code>name</code> goes on a hidden input that carries the value, so <code>FormData</code> and native form posts work. Native mode submits like any <code>{"<select>"}</code>.</Ink>

```jsx
<form>
  <Select name="country" options={countries} />
</form>

// new FormData(form).get("country") → "nl"
```

<Ink as="span"><code>required</code> (or a Field's <code>required</code>) is rendered on the read-only combobox, so assistive technology announces it, but browsers do not run constraint validation on read-only or hidden inputs: the form submits with an empty value. Validate in your submit handler and show the error through Field, or use <code>native</code>.</Ink>

<Ink as="span">Options carry <code>start</code> and <code>end</code> content (an icon, a badge) that renders before and after the label in the listbox. A native <code>{"<option>"}</code> renders text only, so the slots are ignored with <code>native</code>. The trigger shows, and typeahead matches, the label when it is a string or number, otherwise the value.</Ink>

<Callout type="hint">The combobox does not validate `required` natively — validate on submit, or use `native`.</Callout>
