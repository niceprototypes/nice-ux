<Ink as="h2">Guide</Ink>

Input renders a wrapper, the field chrome (border, radius, background, padding,
focus ring), around `start`, the native control and `end`. `className` and
`style` apply to the wrapper. `ref`, `id`, `name`, `aria-*`, `data-testid` and
every native attribute apply to the native control, which stays the focus
target. `onChange` receives the new string value, then the event.

```jsx
<Input className="wrapper-class" ref={controlRef} aria-label="Email" />

// <div class="… wrapper-class">
//   <input aria-label="Email" … />   ← controlRef.current
// </div>
```

`backgroundColor` and `borderColor` take token variants, not CSS colour
strings: a `BackgroundColorType` / `BorderColorType` name, or an object
`{ name, theme?, breakpoint?, inverse?, transform? }`. They resolve through the
`input.backgroundColor` and `input.borderColor` component groups.

```jsx
<Input backgroundColor="raised" borderColor="link" />
```

The native control draws no outline. When anything inside the chrome has
`:focus-visible` (the control, or a button in a slot), the wrapper draws an
outline ring from the `input.focusRing` tokens; it adds no layout. Pointer
focus changes only the border colour.

`start` and `end` sit inside the chrome on the inline-start and inline-end
sides, so they mirror in RTL. Input adds no `aria-hidden`: wrap decorative
icons in `aria-hidden="true"`, and give interactive content such as a clear
button its own `aria-label`.

`width` sizes the chrome from the `input.width` scale. Numeric variants hold
that many characters at every `size`, so the width hints at the expected
answer length. `full` (default) fills the container.

<Callout type="hint">`className` and `style` style the wrapper; `ref`, `id` and `aria-*` go to the native control.</Callout>
