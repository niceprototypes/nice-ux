## Guide

Toggle renders a native checkbox with `role="switch"` inside a `<label>`. The checkbox is invisible but still covers the track, so it stays the focus target, the keyboard handler and the click target; the track and thumb are drawn beside it. Clicking the label text toggles the switch too.

Use it controlled or uncontrolled. Controlled, the parent owns the value through `checked` and `onChange`; uncontrolled, `defaultChecked` sets the starting value and the switch keeps its own state. `onChange` receives the new value first and the native event second, the same order as Input:

```jsx
const [hidden, setHidden] = useState(false)

<Toggle checked={hidden} onChange={setHidden} aria-label="Hidden" />
```

Give every switch a name. Pass the label as `children`, or pass `aria-label` when the switch has no visible label, or `aria-labelledby` pointing at the element that names it.

Inside a `Field` from nice-react-field, the Field's label names the switch, and its description and error describe it. The switch takes the Field's id, `aria-invalid` and `required`:

```jsx
import { Field } from "nice-react-field"

<Field label="Notifications" description="Sent by email.">
  <Toggle defaultChecked />
</Field>
```

`ref` reaches the native checkbox.

| Key | Action |
|---|---|
| Tab | Moves focus to the switch; the focus ring is drawn on the track |
| Space | Toggles the switch |

The thumb slides over the `toggle.transitionDuration` token, and doesn't animate at all when the user prefers reduced motion. Sizes, colors, the disabled opacity and the focus ring are all component tokens, so a theme or a single subtree can restyle Toggle without props:

```css
.settings {
  --np--toggle--track--background-color--checked: var(--np--color--success);
}
```

<Callout type="hint">Toggle applies a change immediately, like a light switch. For a choice that is only applied when a form is submitted, use a checkbox.</Callout>
