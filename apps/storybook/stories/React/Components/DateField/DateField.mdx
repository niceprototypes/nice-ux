<Ink as="h2">Guide</Ink>

DateField v1 is picker-only. The visible Input is read-only and shows the
value formatted with `Intl.DateTimeFormat(locale, { dateStyle: "medium" })`.
The calendar button in Input's `end` slot (accessible name "Choose date")
opens a popover anchored to the field and moves focus to the calendar's
tabbable day. Selecting a day sets the value and closes the popover; Escape or
a pointer press outside closes it, and focus returns to the field. Typed or
segmented entry is not supported yet.

It uses Calendar's ISO contract: `value`, `defaultValue`, `min`, `max` and the
`onChange` argument are `YYYY-MM-DD` strings, and `null` means empty.
`onChange` is typed `string | null`; v1 only ever passes a date string. `min`,
`max`, `isDateDisabled` and `locale` are passed to the Calendar, and
`status="disabled"` disables the calendar button.

Every other Input prop passes through, except `as`, `type`, `end`, `value`,
`defaultValue`, `onChange` and `name`, which DateField owns. `name` is placed
on a hidden input whose value is the ISO date (or `""` when empty); the visible
input has no `name`.

```jsx
<form onSubmit={handleSubmit}>
  <DateField name="start" defaultValue="2026-09-24" />
</form>

// new FormData(form).get("start") → "2026-09-24", not "Sep 24, 2026"
```

DateField renders through Input, so inside a `Field` the visible input takes
the Field's id, label, description and error wiring, `aria-invalid` and
`required` with no extra props. As with Select's combobox, the read-only input
and the hidden input are not validated natively: check `required` in your
submit handler and report it through the Field's `error`.

```jsx
<Field label="Start date" error={error} invalid={!!error} required>
  <DateField name="start" status={error ? "error" : "base"} />
</Field>
```

<Callout type="hint">Forms receive the ISO date from the hidden input — never the locale-formatted text in the field.</Callout>
