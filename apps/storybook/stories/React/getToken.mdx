<StoryHeader title="getToken" />

Resolves a design token. The token name is the only positional argument;
`variant` / `theme` / `inverse` go in an options object (all optional;
`variant` defaults `"base"`). Three sibling functions return the three accessor forms:

- `getToken(name, options?)` — the `var(...)` reference (the common case).
- `getTokenKey(name, options?)` — the bare CSS variable name (no `var(...)` wrapper).
- `getTokenValue(name, options?)` — the raw underlying value (e.g. `"16px"`, an hsla color, a font-family string).

`options`: `{ variant?: string; theme?: string; inverse?: boolean }`. `inverse: true` appends a trailing `--inverse` segment (the opposite-theme value); valid for `color` / `backgroundColor` only.

See [Browse all tokens](/docs/tokens-modules--docs) for a visual reference of every token group.

```bash
npm install nice-react-styles
```

### Setup

```js
import { getToken, getTokenKey, getTokenValue } from "nice-react-styles"
```

### Usage

```js
getTokenKey("fontSize")                          // → "--np--font-size"
getToken("fontSize", "large")       // → "var(--np--font-size--large)"
getTokenValue("fontSize", { variant: "large" })  // → "24px"
getToken("color", "base", { theme: "night" })  // → "var(--np--color--night)"
getToken("backgroundColor", undefined, { inverse: true })          // → "var(--np--background-color--inverse)"
```

Reach for `getTokenValue` when CSS needs the literal underlying value, not the `var(...)` reference — `parseInt` on a duration, a font-family string passed to a chart library, etc. Reach for `getTokenKey` when emitting raw `@property` or `--custom: var(...)` declarations.
