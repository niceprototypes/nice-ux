Pins a subtree to a specific design-system theme (`day` / `night` / consumer-defined).
Renders a layout-invisible `<div data-theme={name} style={{ display: "contents" }}>`
that intercepts the cascading `[data-theme]` rules in `nice-styles/tokens.css`.
All descendants — nice components, raw markup, third-party widgets that consume
`var(--np--…)` — pick up the pin.

```bash
npm install nice-react-styles
```

### Setup

```tsx
import { Theme } from "nice-react-styles"
```

### Usage

```tsx
<Theme name="day">
  {children}
</Theme>
```

---

## Default — follow the browser

When no `Theme` wrapper is present, the design system matches whatever
color mode the browser reports as the user's preference. That preference
usually mirrors the operating system setting, but the browser can
override it (browser settings, DevTools, or extensions like Dark Reader).
Each color variable (e.g. `--np--color`) holds its light
value by default and automatically swaps to its dark counterpart when
the browser reports dark. The swap is handled by the standard CSS rule
`@media (prefers-color-scheme: dark)`, already wired into every color
variable in `tokens.css` — you don't have to write it yourself.

```tsx
<App />   {/* theme follows prefers-color-scheme */}
```

---

## Pin a subtree

Wrap any region to pin its theme independently of OS preference. Children of
the wrapper inherit the pin through the CSS variable cascade.

```tsx
<Theme name="day">
  <Typography>day text</Typography>
  <Icon name="check" />        {/* also pinned to day */}
  <div>raw markup also pins</div>
</Theme>
```

---

## Pin the entire app

In a standard React app, wrap the body of your tree in `<Theme>` directly
inside `StylesProvider`. Every descendant inherits the pin.

```tsx
// App.tsx
<StylesProvider>
  <Theme name="day">
    <Router>
      <Routes>…</Routes>
    </Router>
  </Theme>
</StylesProvider>
```

### Pinning Storybook

Storybook's preview iframe has two rendering paths — **canvas** (a single
story) and **docs** (an MDX page with embedded `<Story>` blocks plus prose).
A standard decorator only reaches the Story subtree; MDX prose around it
does not. To pin everything, wrap at both layers:

```tsx
// .storybook/preview.tsx
import { DocsContainer } from "@storybook/addon-docs/blocks"
import { StylesProvider, Theme } from "nice-react-styles"

const preview: Preview = {
  decorators: [
    Story => (
      <StylesProvider>
        <Theme name="day">
          <Story />
        </Theme>
      </StylesProvider>
    ),
  ],
  parameters: {
    docs: {
      container: ({ children, context }) => (
        <DocsContainer context={context}>
          <Theme name="day">{children}</Theme>
        </DocsContainer>
      ),
    },
  },
}
```

- **`decorators`** covers canvas view and `<Story>` blocks inside docs.
- **`docs.container`** covers MDX prose, headings, paragraphs — anything
  rendered outside a Story block on a docs page.

This storybook uses exactly that recipe in `.storybook/preview.tsx`. Note:
storybook's own UI chrome (the sidebar and toolbar) is rendered in a
separate **manager** iframe themed via the storybook `create({ base })`
API and is independent of nice tokens. Pinning nice theme affects only the
preview iframe.

### Fallback for unusual hosts

If you don't have a React entry point you can wrap (e.g. you're integrating
nice tokens into a non-React codebase), set the attribute on `<html>`
directly. Same mechanism the `Theme` component uses.

```ts
document.documentElement.setAttribute("data-theme", "day")
```

---

## Nested pins

Inner `Theme` wrappers override outer ones — the cascade resolves to the
nearest `[data-theme]` ancestor.

```tsx
<Theme name="day">
  <Typography>day text</Typography>
  <Theme name="night">
    <Typography>night text inside a day region</Typography>
  </Theme>
</Theme>
```

The component-level `theme` prop on Typography, Tile, Button, Icon, Image, and
Input is implemented in terms of `Theme` — setting `<Tile theme="night">` is
equivalent to wrapping Tile in `<Theme name="night">`.

---

## When `theme` is explicit

Children that set their own `theme` prop pin themselves and override any
ancestor `Theme` wrapper. Useful when one element inside a pinned region needs
the opposite theme (a "night" inset inside a day-pinned page, etc.).

```tsx
<Theme name="day">
  <Tile>            {/* day */}
    <Typography>day text</Typography>
    <Typography theme="night">night text</Typography>
  </Tile>
</Theme>
```

---

## How it works

`tokens.css` emits two pin blocks at the end of the stylesheet:

```css
[data-theme="day"]   { color-scheme: light; --np--color: var(--np--color--day); /* … */ }
[data-theme="night"] { color-scheme: dark;  --np--color: var(--np--color--night); /* … */ }
```

The attribute selector outranks the `@media (prefers-color-scheme: dark)`
rule, so the pin wins over OS preference. Stable theme primitives
(`--np--…--day` / `--np--…--night`) are never reassigned — components that
emit direct primitive references (rare; usually only for inverted-theme
escape hatches) bypass the cascade entirely.
