The **Nice Manifest** lives beside the code at `~/nice/manifest`. Every pattern, convention, and piece of logic an AI instance needs to work on a `nice-*` package is documented there — if it is not in the manifest, an AI instance will not know it exists.

<HorizontalRule />

## Load model

"Read the manifest" does not mean read all 40+ files. It loads the always-on **Core**, then lazy-loads a topic body only when the task touches it.

| Layer | Loads | When |
| --- | --- | --- |
| **Core** | all of `discipline/` + the root `README.md` index | always |
| **Topics** | the `read/` `edit/` `build/` `publish/` `topics/` files | on demand |

<Callout type="learning">An agent cannot load a topic it does not know exists. The root README's File Tree names every file and its purpose, so the right doc is always discoverable from the Core.</Callout>

## Principles

**The token system is the origin pattern.** The token generation system in `nice-styles` — token JSON to generated data, types, and CSS, to runtime getters and setters — is where the ecosystem starts. Every other package builds on it. A package that cannot reach logic it needs through the token system is a showstopper: stop, report the gap, fix the token system first.

**Alignment.** The `nice-*` packages are one system that publishes under separate names for distribution only. Anything shared — TypeScript version, build config, lint rules — belongs in a foundation package, used by every consumer at the same version. Divergence is a defect to fix.

<Callout type="hint">Artifacts have fixed homes: an audit report goes to `manifest/.reports/audit/{slug}.md`, a research report to `manifest/.reports/research/{slug}.md`, and a per-package change record to that package's `.nice/bump.md`.</Callout>
