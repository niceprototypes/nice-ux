## getIcon

The vanilla-JS counterpart to `<Icon>` — returns an icon's **SVG markup as a
string**, ready to inject without writing HTML or JSX. Styled from the same
`icon` tokens as the component (size, color, stroke width).

```js
import { getIcon } from "nice-icons"

getIcon("check")                                             // base variant (default)
getIcon("check", "fill")                                     // fill variant
getIcon("check", "base", { size: "large", color: "link" })  // configured

// Inject anywhere:
document.querySelector("#slot").innerHTML = getIcon("check")
```

## getIconEncoded

An icon's SVG as a **base64 data-URI** — the encoded counterpart to `getIcon`.
The color is **baked in** (`base` = black, `night` = white), so it renders
standalone with no CSS cascade: drop it straight into an `<img src>`, a CSS
`url()` / `background-image`, or a `mask-image`.

```js
import { getIconEncoded } from "nice-icons"

getIconEncoded("check")                              // base variant, base theme (#000)
getIconEncoded("check", "fill")                      // fill variant
getIconEncoded("check", "base", { theme: "night" })  // white glyph (#fff)

// → "data:image/svg+xml;base64,PHN2Zy…"

// Use directly as an image or CSS asset:
element.style.maskImage = `url("${getIconEncoded("check")}")`
```

The sibling `getIconEncodedKey` returns the **bare base64 payload** (no
`data:image/svg+xml;base64,` prefix) for when you compose the data-URI yourself.
The full set is also available as a raw map at `nice-icons/base64` — per-icon
`base64.json`, keyed name → variant → theme.

<Callout type="hint">`getIcon` resolves color from `icon` tokens and flips with the theme cascade; an **encoded** icon has its color baked in, so pass `theme: "night"` for a white glyph. Ideal for `mask-image` (where the fill comes from `background-color`) and static `<img>` use, where no CSS cascade reaches the SVG.</Callout>
