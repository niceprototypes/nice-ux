# Stories

Storybook (`apps/storybook`) is the bedrock: every scenario a component supports is isolatable and reproducible through Controls/args. Example: Button filled, with an icon and changed text, reproduces a render bug from the Controls panel alone.

## One Playground per component

- File: `apps/storybook/stories/Components/{Component}/{Component}.stories.tsx`. Title `Components/{Component}` (grouped: `Components/Forms/{Component}`; each group needs an entry in `.storybook/preview.tsx` `storySort` before `"*"`).
- `export const Playground: Story` with `args` for every prop and `argTypes` giving each a control. Reference: `stories/Components/Tile/Tile.stories.tsx`.
- Union-typed props are `select` controls whose options are typed against the union on disk, so a renamed token fails the build:
  ```ts
  const SIZE_OPTIONS = ["smaller", "small", "base", "large", "larger"] as const satisfies readonly SizeType[]
  ```
- Nested object props are flattened into scalar args (one control each) and recomposed in `render`; the recomposed object is type-checked against the component's props.
- An explicit `select` overrides `preview.tsx`'s matcher that turns any arg ending in `color` into a colour picker.
- A state with no controlling prop (CSS `:hover`, internal `open`) is listed as missing controllability in the report, never faked with synthetic DOM events.
- Every new prop lands in the Playground and its test in the same change.

## UI tests

`play` functions on Playground variants (`import { expect, userEvent, within } from "storybook/test"`), one per prop or state, asserting rendered output for given args. No test runner is installed yet; choosing and wiring it is part of the Storybook rework (backlog row 12). Until it runs, a component change is reported unverified (`../discipline/manager.md` → Evidence).

## Galleries

Only where comparison is the point: type styles, colours, token tables (`stories/Tokens/`, generated by `scripts/generate-token-stories.mjs`). Per-prop gallery pages (`{Prop}.mdx`), example tables and `Lifecycle.mdx` pages are being replaced by Playgrounds and tests; do not add new ones.

## Docs page

`{Component}.mdx`: `<Meta of={Stories} />`, a one-sentence description, install line (`@niceprototypes/{name}`), a minimal usage block, `<Stories />`. Keep titles stable; they are the story ids in `agents/catalog.json`.

## CSF constraints

- Meta is inline in the stories file and uses `satisfies Meta<typeof Component>`; `export default meta`. Imported or re-exported meta breaks Storybook's static analysis.
- Layout: `padded` by default; `fullscreen` for full-width components (Tile, Scroll, Slider).
- A package a story imports must be in `apps/storybook/package.json` (`workspace:^`), or `tsc` reports TS2307.
- Boolean-discriminated props (Select `native`): branch the JSX per variant. Select `children` is an array, not a Fragment.
